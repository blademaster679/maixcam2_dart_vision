# 独立模型线程的绿灯中心原型

`board_async_center_fps.cpp` 在 `board_fast_center_fps.cpp` 的原生 NV21 局部定位原型上拆分模型工作。它是独立的板端测试程序，未接入正式控制应用。

主线程按最新帧进行绿灯区域定位与有效性判定；工作线程执行模型区域 RGB 转换、NPU 推理和源图像坐标匹配。每个任务包含不可变图像引用、候选中心、源帧时间戳和跟踪代次。缓存图像在工作线程退出前一直有效。真实相机接入时必须换成有生命周期保证的帧租约或独立裁剪缓冲，不能传递即将复用的相机裸指针。

`dart::LatestWorker` 最多保留一个等待任务，新任务替换尚未执行的旧任务。完成结果被消费之前不会启动下一次任务，避免否定结果被后续肯定结果覆盖。主线程读取结果不等待推理。线程异常在主线程重新抛出；析构丢弃待执行任务并等待正在执行的任务完成。底层推理若卡住仍会使 join 等待，本回放另有进程级 timeout，不构成生产级 NPU 故障恢复。

模型结果仅确认其源帧所属轨迹，不直接用作当前帧位置。接受条件是：跟踪仍存在、代次相同、源帧时间戳更新且不超过 100 ms。负确认立即清除有效状态；当前像素定位失败也会清除并更新代次。尚未确认的候选可继续局部追踪，但至少两次模型肯定后才输出观测。没有用预测值替代测量，没有降低原模型置信度阈值。

为适配异步返回，未确认候选也需保留轨迹。模型不再把旧帧中心写回当前中心；这是与串行原型有意保留的行为差异，因此结果不是仅替换一行线程代码的严格等价试验。

构建（需要已有同 SDK 的正式应用构建产物，输出目录必须不存在）：

```sh
python3 tools/model/build_video_model_fps.py \
  --source tools/model/board_async_center_fps.cpp \
  --out artifacts/vision_optimization_20261007/async_new_build
```

在板端已部署应用目录执行，模型和动态库沿用现有配置：

```sh
LD_LIBRARY_PATH=./dl_lib:/opt/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH} \
  timeout 90 /path/to/board_async_center_fps \
  /path/to/clip13.mp4 green_detector.conf 26 20 /tmp/result.csv /tmp/result.json
```

程序拒绝覆盖结果文件，要求启用 center_only 模型。启动时缓存 90 张原生 NV21 图像，20 秒测试按 180 Hz 循环取最新帧，统计 [3,19.5) 秒。内存不足会拒绝运行。该实验排除解码、摄像头和通信；不是完整连续视频准确率验收。

CSV 的 model_ran 表示该主线程迭代消费了已完成模型结果；model_valid 表示该结果被接受且肯定。submitted 和 rejected_results 是整次运行计数，Hz 是排除预热后的窗口计数。观测年龄与模型确认年龄不同，确认有效期为 100 ms，不应把低观测年龄理解为模型刚刚确认过每一帧。

审计命令：

```sh
python3 tools/model/analyze_fast_center_fps.py \
  artifacts/vision_optimization_20261007 --prefix async_v2_s
```

单元测试 `latest_worker_tests` 验证不阻塞读取、待执行任务替换及线程异常传递；CSV 审计验证观测来自当前像素、肯定结果代次一致、确认未过期、负确认后不输出。性能、失锁间断和验收边界见同目录产物 `ASYNC_REPORT.txt`。

## 完整离线视频

`board_async_center_full.cpp` 顺序解码原生分辨率每一帧，保留跟踪状态，以原视频时间戳推进确认间隔和有效期。工作线程持有 `shared_ptr<const CachedFrame>`，保证不会读取下一帧复用后的数据。其确认与局部定位逻辑来自异步短片段版本。

该回放保留每帧，而非 180 Hz 定时丢弃旧帧。慢速软件解码给模型线程更多运行时间，因此不能用它证明真实 180 Hz 输入下的调度、60 Hz 连续观测或曝光至输出延迟。它验证完整输入覆盖、异步结果处理和逐帧识别表现；没有人工标注时，不给出误检率、漏检率或中心误差。

完整模式 CSV 的 `wall_end_ms` 是实际完成时间，`decode_ms` 包含解码与 NV21 转换，`work_ms` 是主线程定位/提交耗时。为了兼容表结构，`end_ms` 为源时间加 work_ms，`age_ms` 等于 work_ms；这两个兼容字段不用于端到端延迟评估。模型时间与主线程有重叠，不应把两者相加后称为吞吐。

`render_async_center_full.py` 逐行审计并渲染全片，核对板端原片 SHA256、帧数、原分辨率、180 FPS 和时长。视频中吞吐按最近 180 个源帧对应的实际墙钟时间计算，包含解码；绿灯标记仅来自当前帧有效测量，模型旧帧坐标不转贴到新帧。未输出区间可能包含原本没有目标的画面，不能全部称为漏检。

## 卡尔曼输出平滑

`dart::CenterKalman` 已接入异步短片段与完整回放程序的观测输出阶段。原始 `x/y` 保持不变，增加 `smooth_valid/smooth_reset/smooth_x/smooth_y` 字段；需要平滑坐标的消费者读取 smooth 字段，不能把旧版 x/y 当成已经平滑。正式控制主应用尚未接入这套原型。

模型为两个独立的“位置 + 速度”卡尔曼滤波器，按源图像微秒时间戳更新，常规过程噪声谱密度为 250000 px²/s³，测量标准差为 clamp(0.06×灯直径, 1.5, 4) 像素。二维归一化创新大于 16 时增加位置协方差以跟随运动，避免一味加大平滑导致拖尾；超过 max(40,4×直径) 的突变重置到新测量。滤波不是误检分类器，大跳变仍可能被接受。

仅当前图像有效观测参与输出。失锁、否定确认后的无效观测、轨迹代次变化、非递增时间戳以及超过 50 ms 的观测间隔均重置或清除状态；不输出纯预测点，不借滤波增加观测率。无未来帧、无等待窗口。计算开销小不等于动态滞后为零，30 ms 全链路要求仍需真机验证。

`filter_center_csv.cpp` 使用同一个 C++ 头文件在板端重放已保存的完整观测，避免重新跑识别造成输入差异。输出滤波不回馈 ROI 或 NPU，所以它能验证这一路输出处理，但不是重新执行完整模型推理。板端与主机逐帧结果核对小于 1e-6 像素。

对比视频由 `render_async_center_full.py --smooth` 生成：绿色平滑中心、蓝色原始中心。视频 FPS 沿用原完整离线识别结果，不伪装成本轮重新跑过的吞吐。新增耗时、实供帧回归与轨迹二阶差分粗糙度在 `artifacts/center_kalman_20261007/REPORT.txt` 中说明。粗糙度包含真实运动加速度，不能作为真值定位误差或准确率。

## 有限时长预测与跳点拦截

`PredictiveCenter` 是独立的输出状态层，保留已有原始观测和卡尔曼字段。新增 `output_valid/output_predicted/jump_rejected/output_reacquired/output_x/output_y/observation_age_ms`，控制消费者需要显式读取这些字段；原始 observed 统计不变。当前只接入独立回放原型，正式控制程序尚未替换。

仅从至少三次已被模型确认的测量启动输出。短缺测时按图像平面速度外推，最长 60 ms；20 ms 后速度贡献逐渐衰减，垂直外推更保守。静止微小速度归零。横向速度限 1000 px/s，纵向限 300 px/s，不能把它们当作角速度；没有相机标定和 IMU 时也不能将 yaw 运动简单等同于完全不变的像素 y。

测量与预测采用椭圆门限，横向基础门限 clamp(直径,32,80) 像素，纵向 clamp(0.6×直径,24,48) 像素，再随速度与观测年龄适当放宽。明显跳远的测量先拒绝，继续有界预测；不会立即重置到远点。新检测代次需空间连续确认。预测超时先输出无效，再进行三次新位置确认，重捕获显式标记；合法的新目标位置仍可能与旧位置相距很远，消费者不能跨无效段盲目连接轨迹。

接受的模型否定、时间倒退、非有限输入或预测出图立即停止输出。单纯漏检造成的检测代次变化不会自动取消短时外推。该层不改变 NPU 身份判断、不将预测反馈给候选搜索，也不会增加真实视觉更新频率。长于 60 ms 的失锁和模型否定造成的空白不被预测掩盖。

`predict_center_csv.cpp` 在板端重放既有全片原始观测；为复用渲染表结构，文件内 smooth_* 表示本版输出，output_predicted 区分预测。对比视频使用 `--predict`，黄为预测、绿为测量更新、蓝为原始点，固定准星不表示灯直径。全片没有自然发生的大幅连续帧跳点样本，远跳抑制另由合成测试覆盖，不能报告虚构的真实误检剔除数量。

## 稳定轨迹确认与原区域恢复修正

`ModelConfirmationGate` 仅处理已接受、同代次的模型结果：尚未建立的候选一次否定即退出；已累计至少两次肯定的轨迹需要连续两次否定才退出。一次肯定清除否定计数。单次否定并不刷新 last_positive，既有 100 ms 肯定有效期仍然生效，且本帧仍必须通过局部像素定位才能计为观测。

`hard_reject` 与 `result_generation` 一起传给预测层。只有被否定的代次等于预测层当前关联的代次时才撤销旧预测；另一个候选的否定不能清除旧轨迹。单次否定容忍不代表该帧模型肯定，原始 model_valid/raw_model_valid 日志仍保留否定，避免掩盖模型问题。

重捕获优先在最近一次已确认的中心附近 32 像素门限内测量，最多保留这次已确认测量后的 100 ms。未确认候选不能更新恢复锚点或延长这个窗口。局部找不到才退回全局候选搜索。首轮将所有候选都作为恢复锚点导致退化，最终修订修复了这一点。

完整回放程序可附加 START_SECONDS DURATION_SECONDS 执行有界逐帧区间回归，输出 complete_source=false、complete_range=true、start_seconds。区间 sequence/source clock 从区间第一帧开始，不可与整片绝对帧号混用。每段独立启动且保留预热；与旧整片状态不同，因此对比不是严格相同历史状态的逐帧 A/B。`analyze_tracking_recovery.py` 按区间偏移核对问题窗口。

本次只验证问题窗口与无目标窗口，不代表完成全片新模型精度或真实相机验收；单次否定容忍仍需扩大错误目标测试。正式控制程序未替换。
